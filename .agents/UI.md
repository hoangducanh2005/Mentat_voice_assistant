# Engineering UI Specification: Mentat Voice Assistant Dashboard (V2)

This document details the visual and functional specification for the Mentat Voice Assistant engineering dashboard. The interface is designed to transform a backend AI pipeline into a tangible, production-ready enterprise product demo for hardware and software engineers.

---

## 1. Design Philosophy & System Vibe
Instead of a conversational chat interface (like standard LLM web apps), this interface acts as an **Engineering Cockpit**. It prioritizes transparency, data visibility, and system metrics to showcase real-time Edge AI processing.

* **Theme:** Industrial Dark Mode (Deep charcoals, slate grays, and matte blacks).
* **Accents:** Cyberpunk-inspired desaturated Amber (representing the Dune Spice Melange) and Cobalt Blue (representing the Eyes of Ibad).
* **Typography:** Sans-serif structural fonts (`Inter` or `Roboto`) for conversational text; Monospace fonts (`JetBrains Mono` or `Fira Code`) for system metrics, RAG chunks, and processing logs.

---

## 2. Layout Architecture

The dashboard is structured into a unified grid composed of three functional zones, ensuring all data flows are visible on a single screen without requiring scrolling.

### Zone 1: Visual Feedback & System State (Top / Center)
This area anchors the user's attention, providing immediate visual feedback on the state of the local microphone and processing loop.

* **State-Reactive Simulated Waveform:** An animated canvas that triggers a predefined, smooth geometric wave animation whenever voice activity is detected (`LISTENING` or `SPEAKING` states). It bypasses complex, resource-heavy real-time pitch/frequency analysis (FFT) to completely decouple frontend rendering overhead from backend audio processing, maintaining identical, consistent wave dynamics regardless of vocal volume or pitch.
* **System State Indicator:** A clear, high-contrast label displaying the current execution thread:
    * `IDLE`: System is waiting for voice activity.
    * `LISTENING`: Voice activity detected; capturing audio stream.
    * `THINKING`: Processing ASR, matrix operations, and LLM orchestration.
    * `SPEAKING`: TTS engine is actively streaming audio to the speakers.

### Zone 2: Communication Transcript (Left Column)
Tracks the verbal exchange between the user and the Mentat, featuring an intelligent post-processing display.

* **User Transcript Box:**
    * Displays the raw ASR text output in a muted color.
    * If a custom text-correction rule is triggered (e.g., converting "menta" to "Mentat"), the raw text is struck through, and the finalized, cleaned keyword is highlighted.
* **Assistant Response Box:**
    * Renders the text response generated by the LLM.
    * Text streams character-by-character to match the exact vocal output of the Text-to-Speech (TTS) engine.

### Zone 3: RAG Core & System Analytics (Right Column)
The primary "show-off" window that proves the system is utilizing local knowledge retrieval rather than hallucinating or blindly calling a generic API.

* **Telemetry & Latency Logs:** A terminal-style scrolling window displaying microsecond-accurate logs from the backend:
    * `[INFO] VAD triggered in 12ms`
    * `[INFO] ASR execution completed (Latency: 0.82s)`
    * `[INFO] Cosine Similarity calculated across 603 chunks (< 1ms)`
* **RAG Context Cards:** A stack of interactive visual cards rendering the top-K retrieved text blocks from the local database (`vectors.npz`). Each card exposes:
    * **Source Filename:** (e.g., `Arrakis.txt`, `Paul_Atreides.txt`)
    * **Confidence Score:** The exact mathematical Cosine Similarity score formatting (e.g., `Similarity: 0.7839`).
    * **Text Snippet:** The raw text slice that was injected into the prompt payload.

---

## 3. End-to-End Interactive Demo Flow

When a user triggers the system, the UI visually mirrors the technical pipeline across the three zones:

1.  **State Change (Listening):** The simulated waveform activates in Zone 1. The state changes to `LISTENING`.
2.  **ASR Completion:** Zone 2 populates with the user's spoken words. The system updates the state to `THINKING`.
3.  **Retrieval Phase:** Zone 3 flashes. The telemetry terminal prints the execution times, and the top-3 matching data cards slide into view, displaying their mathematical confidence scores.
4.  **LLM Formulation:** The exact prompt structure (Context + Preprompt + Query) is visualized as a compiled payload before it hits the completion endpoint.
5.  **Vocal Output (Speaking):** Zone 1 switches to `SPEAKING` as the simulated waveform pulses in sync with the audio playback. Zone 2 streams the text response simultaneously.
